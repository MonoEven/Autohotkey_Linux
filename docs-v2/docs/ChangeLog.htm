Changes & New Features

Linux port: the sections below this box are the upstream Windows AutoHotkey v2.0.26 changelog. The Linux port's own changes are listed first. See Linux Port for the current release and backends.

Linux port changes

Unreleased (check_detail0824 M0)

  • Versioned input capability contract: HotkeyBackendGet() and ahk_core --diag now expose caps_version=2, scan-code/custom-combo/character-stream, synthetic provenance strength, SendLevel gating and direct-Unicode fields. The backend table and Linux documentation are generated from one source; CI rejects drift.
  • M0-B correctness fixes: AT-SPI text now decodes complete UTF-8; GNOME Xorg is no longer misclassified as Wayland; failed X11 grabs stay out of the installed set and automatically recover after their former owner exits. Current branch totals are 1148/1148 X11/headless, 17/17 Wayland and 230/230 XWayland assertions.
  • M0-C honesty and provenance: Windows DLL specifications and known Windows COM ProgIDs now raise migration-specific errors instead of being reinterpreted as Linux libraries/D-Bus names. Release-tag packages use GitHub Artifact Attestations (Sigstore/SLSA Build L2); packaging no longer generates ephemeral OpenPGP identities and emits an explicit unsigned marker when no pinned long-term key is configured. Current X11/headless total: 1152/1152.
  • M1-O external input oracle: an independent XI2.1 recorder now captures AHK Send output as schema-versioned JSONL (order, timing, device/source IDs and XTEST provenance), while a separate XTEST process injects a key which AHK must capture. CI uploads the trace and summary; the permission-gated VM lane retains a separate uinput device oracle.
  • M1-K three-layer key model: xkbcommon-x11 now supplies the active physical evdev/set-1 scan code, logical VK/keysym and Unicode-text layers. Explicit scXXX hotkeys work on X11 and evdev; InputHook reports canonical VK/SC values; Send resolves Shift/AltGr bindings from the live layout before borrowing a Unicode keycode. A deterministic external oracle verifies physical sc01E across US/AZERTY and EuroSign on an AltGr-only level.
  • M1-C evdev custom combinations: the evdev lane implements prefix state for A & B, wildcard modifiers, key-up variants, tilde passthrough and delayed/cancelled standalone-prefix hotkeys, including explicit scan-code prefixes/suffixes. X11/portal/GNOME keep custom_combo=false and reject registration until the M2 raw event path can implement them without fragile passive grabs.
  • M2-R XI2 raw capture: Hotstrings and visible InputHook now share an observation-only XI2.1 stream. Two scripts can observe the same input while the target receives original send_event=False events; Hotstring replacement uses exact Backspace counts instead of holding and synthetically forwarding every key. Suppression requests stay on a separate compatibility-grab lane.
  • M2-L selected suppression: InputHook now installs passive grabs only for keycodes which its visibility/KeyOpt policy actually suppresses; raw observation handles the rest. Runtime KeyOpt changes reconcile the set immediately, canonical secondary scan codes distinguish Enter/Numpad and navigation/numpad variants, and an independent XGrabKey oracle proves exact scope and target visibility. InputHook EndReason/EndKey now follows the official v2 contract for both keycode and E-character modes. Current branch totals: 1139/1139 X11/headless, 17/17 Wayland, 234/234 XWayland.
  • M3-E normalized input events: version-1 events carry physical evdev/set-1 SC, logical VK, Unicode text, phase/repeat, source, SendLevel, device and origin across X11, evdev, Portal and GNOME Shell entry points. The schema is queryable from HotkeyBackendGet/--diag and an optional JSONL trace has independent self/other/physical provenance oracles.
  • M3-M per-hotkey input mux: hotkeys are routed by capability to X11, portal, GNOME Shell or evdev, and multiple lanes can be registered and pumped at once in one script (each backend only owns its assigned keys). The active composition is exposed as HotkeyBackendGet().mux and --diag input-mux; runtime Hotkey changes differentially start/stop lanes. A scenario proves XTEST F12 (X11) and a uinput a & b (evdev) fire concurrently in the same script.
  • M4-D ahk-inputd broker: a new standalone ahk-inputd daemon captures every keyboard with EVIOCGRAB, replays unconsumed keys via a 0x0FAC virtual device and distributes length-prefixed v1 frames over a UNIX socket to multi-client subscription rules (with per-key want_suppress arbitration). Client crashes clean rules instantly; a SIGALRM watchdog and the Backspace-Esc-Enter panic release grabs on a stuck loop. An independent VM oracle proves distribution, replay, suppression, client-crash cleanup and grab recovery after broker death. The core client that consumes these frames lands with M4-C.
  • M4-C broker client: with AHK_INPUT_BACKEND=evdev the core first tries the ahk-inputd socket (HELLO + SUBSCRIBE from the EVDEV-assigned hotkey table, tilde clears suppression), consumes EVENT frames through the same combo/scXXX matcher and falls back to the in-process lane when no broker is reachable. Two scripts in one VM share the broker stream and both fire a & b / c & d without BadAccess. The shared protocol header lives in inputd/inputd_proto.h.
  • M4-C2 broker character stream: when Hotstring/InputHook capture is active under AHK_INPUT_BACKEND=evdev, the mux activates the broker lane, subscribes text-producing keys (no suppression, matching the M2-R backspace model) and decodes broker EVENT frames through the three-layer model into the capture engine; XI2 raw skips capture in broker mode to avoid double feeding. A VM oracle proves a :B0X*:pq Hotstring fires from broker-distributed uinput events. Pure Wayland still lacks a layout source for broker char_stream, and the libei/InputCapture receiver remains upstream-gated.
  • M5-A EWMH window enumeration: Win*/Control enumeration now prefers the root _NET_CLIENT_LIST (real WM client windows), and falls back to XQueryTree with an ICCCM WM_STATE subtree probe when no window manager is present, keeping unmanaged test windows visible. An independent oracle proves the EWMH list wins and the no-WM fallback stays unchanged.
  • M5-B Control* virtual-state retirement: style/exstyle/enabled/ checked, the Combo/List family, the Edit virtual caret and ListView row filling now throw a clear NotSupported (OSError) on external windows instead of mutating a fake in-process store; text reads/writes stay real. The gate keys off the top-level _NET_WM_PID, so windows this script created can still use the semantics. Assertions moved to NotSupported coverage (1135/17/230 totals).
  • M5-C AT-SPI WinTitle limiting: Control* on a native-Wayland session now resolves the WinTitle to its owning application (D-Bus destination) and searches only that app's accessible subtree, so same-named controls in different applications no longer cross-match. Application-root placeholder nodes are skipped when matching a control name. An independent two-process GTK oracle proves ControlGetText("OK","WintA") and ("OK","WintB") resolve inside their own applications.
  • M5-C AT-SPI bulk cache: discovery reads each application's org.a11y.atspi.Cache.GetItems once (500ms call budget) instead of issuing GetChildren/Name calls per node. Unsupported and Qt old-signature caches fall back per application. Each refresh has a 2s total deadline and returns its partial table on expiry; diagnostics expose cache/fallback/item and budget state. VM oracles prove cache, fallback and a 1ms fault-injected timeout while preserving UTF-8 text results.
  • M5-C A_ControlSendMode: the writable Linux variable accepts focus (existing X11 focus/send/restore behavior) or atspi. AT-SPI mode appends plain Unicode text to EditableText without an X display and maps Enter/Space to Action; complex Send syntax is rejected explicitly. CI covers the variable contract and a GNOME oracle proves real Base-世界 text without focus fallback.

v2.0.26-linux.15

check0820 direction-B core (round-37):

  • Hotkey() reaches the Wayland backends: the old X-only guard (“no global hotkey protocol; use XWayland”) made Hotkey() fail on every Wayland session before the backend could be consulted. It now routes by the resolved input backend (gnome-shell/portal/evdev) through LinuxInputBackendSync(), with per-backend error surfacing (verified live on GNOME 49).
  • GNOME Shell extension backend end-to-end: the Activated sender check compared the signal sender against the broker’s well-known name, but D-Bus delivers unique bus names (:1.NNN); the handler now caches the broker’s unique name (GetNameOwner, refreshed on NameOwnerChanged). The extension’s own version-guard import (import {Config}) was broken on GNOME 49 (the module is a namespace export) - fixed to import * as Config. VM-verified end-to-end: F12 and Ctrl+1 fire, and extension disable → enable re-registers automatically (dedicated GNOME VM test scripts).
  • AT-SPI control automation: ControlGetText, ControlSetText and ControlClick now use the org.a11y.atspi bus in Wayland sessions (text read / editable-text set / Action.DoAction("click")); fixed the Control/WinTitle parameter indexing and the session gate (GNOME Wayland with XWayland present must still take the at-SPI path). Verified on a GTK3 app: read label → click button → label changed.
  • IME active-state detection: new ImeGetState() builtin returns framework|group (ibus/fcitx5 by session-bus owner; current XKB group on X11). Preedit read, IME toggling and wlroots input-method-v2 text delivery are recorded as out of scope with the concrete reasons (mutter links no input-method symbols at all; sway ships only v1 XML and no v2 backend) in docs/IME-Integration.md; a client scaffold documents the v2 bind shape.
  • Clipboard slow-owner timeout: AHK_CLIPBOARD_TIMEOUT_MS (default 2000) bounds the X11 SelectionNotify and Wayland offer/receive waits; a slow app that only serves after 2.5 s times out cleanly at the default and succeeds when the env is raised (regression: assert_clipboard_slow, 4 assertions).
  • Portal deny/cancel regression: with the extension disabled the portal backend is active; an ungranted bind must not crash, must not fire, and must exit cleanly on SIGTERM (GNOME VM regression script). The interactive GNOME permission dialog itself is not automatable headlessly - recorded in audits/check0820.md.
  • evdev/uinput permission model: tools/linux/permissions/ ships the udev rule (/dev/uinput 0666), the input-group setup for reading /dev/input/event*, a polkit action for a future privileged capture helper, and an install script (VM-verified).
  • Doc-check: 1099/1099 assertions pass on both the normal and the ASan builds; regression 27/27, Wayland 17/17, XWayland 247/247 (counts are machine-verified in CI by verify_report_numbers.sh).

v2.0.26-linux.14

Reliability fixes from the check0820 review (round-36):

  • Passthrough copy no longer swallows genuine repeats: the re-grabbed-copy suppression is now consume-once (each mark matches at most one event) with a short 250 ms window, so double letters (ll/oo), held-key auto-repeat and double-taps fire the hotkey AND reach the foreground instead of being filtered by a stale record. (Regression: assert_hotkey_pt adds a rapid two-press ~F11 case.)
  • Unicode spare-keycode borrows are cross-process safe: the temporary keyboard-mapping change is serialized through an X selection lease (AHK_UNICODE_BORROW_LEASE); a second AHK process waits (bounded) or reports the character undeliverable instead of overwriting the first process’s mapping mid-borrow. A crashed process releases the lease automatically.
  • Wayland clipboard-paste fallback hardened: the paste waits for the target application to actually request the offer (instead of a fixed sleep), restores an originally-empty clipboard to empty, can be disabled entirely with AHK_WAYLAND_PASTE=0, warns once before first use (sensitive text/password managers), and its wait is tunable via AHK_WAYLAND_PASTE_TIMEOUT_MS.
  • uinput injection lane: Send/Mouse* can now fall back to a persistent uinput virtual keyboard/pointer when the compositor has no virtual-keyboard protocol (GNOME/KWin; needs /dev/uinput access, e.g. the input group); AHK_UINPUT=0 disables it. Non-ASCII Send on such compositors uses the paste fallback whenever a lane can deliver the Ctrl+V.
  • GNOME Shell extension version range: shell-version now declares 45–50 (the grab_accelerator + allowKeybinding API surface is stable across the series); a runtime warning is logged when loading on a major other than the verified 49.
  • Release policy: from this version on every release stays published (upgrade and downgrade via ahk --update <VER>), each with a CKSUMS.txt (SHA-256) generated by pack.sh and verified in CI.
  • Doc-check: 1069/1069 assertions pass on both the normal and the ASan builds; regression 27/27, Wayland 17/17, XWayland 247/247 (counts are machine-verified in CI by verify_report_numbers.sh).

v2.0.26-linux.13

Unicode text input (round-34): SendText/Send and hotstring replacements now deliver non-ASCII characters (Chinese, Japanese, Korean, accented Latin, Emoji) on X11/XWayland via Unicode keysym transmission (a spare keycode is temporarily remapped when the layout has no binding, xdotool-style, with race fixes for late event consumers and a process-local FIFO borrow log); on pure Wayland (wlroots) non-ASCII runs use the controlled clipboard-paste fallback; compositors without a virtual keyboard (e.g. GNOME) raise a clear error naming the character instead of silently dropping it. Also fixes the Wayland virtual-keyboard letter keycodes (evdev letters are QWERTY-ordered; KEY_A + offset mapped 'V' to KEY_COMMA, which broke the paste path's Ctrl+V).

InputHook notifications: OnChar/OnKeyDown/OnKeyUp are now delivered (Windows semantics: VK/SC for keys, SC = X11 keycode; the character for OnChar, Unicode included), queued by the capture engine and fired from the main-loop dispatch. Hotstrings match Unicode trigger words character-for-character.

GNOME Shell backend hardening: activations are directed to the registering owner (never broadcast), hotkey ids are owner-scoped (<unique-bus-name>/<hotkey>), ClearOwner takes no owner argument (the caller's own unique name is used), only Activated is consumed, registrations use batch methods (RegisterMany/UnregisterMany) with bounded timeouts, and the event queue is dynamic with overflow counting.

Configuration correctness: AHK_FORCE_GLOBAL_SHORTCUTS only treats 1/true/yes/on as true; unknown AHK_INPUT_BACKEND values print a clear startup warning. Reporting: assertion counts in CHECK_REPORT.md are now machine-verified against the expect files by tests/doccheck/verify_report_numbers.sh in CI (doc-check 1063/1063, regression 27/27, Wayland 15/15, XWayland 247/247). The project is positioned as a technology preview; see Linux Port for the compatibility matrix and roadmap (evdev/ahk-inputd, IME, AT-SPI), and the credits for AHK_X11.

v2.0.26-linux.12

Unified input backend (AHK_INPUT_BACKEND=auto|x11|portal|gnome-shell|evdev) and a new GNOME Shell extension backend for GNOME 49 Wayland: zero-confirmation exclusive global hotkeys (1::/^1::/F12:: grab the physical key with no per-binding dialog), automatic re-registration after a shell/extension reload, and fail-open release on exit or crash. The XDG Global Shortcuts Portal backend stays the standard fallback (KDE/other Wayland); AHK_FORCE_GLOBAL_SHORTCUTS=1 keeps its documented meaning.

Launcher rework: commands are now -- prefixed (ahk --version shows the release, e.g. v2.0.26-linux.12; ahk --check verifies integrity/install method/latest release; ahk --uninstall; ahk --update [VER]) so plain names like update.ahk are always run as scripts. The Debian package now ships the full launcher instead of a bare exec, and its postrm cleans up any launcher residue left behind by dpkg-mismatched files (e.g. a wrapper clobbered by a tarball install), so apt remove never strands an ahk command. Older releases with outdated launchers were removed from the Releases page — only the latest release is published, so ahk --update can never install a version whose launcher lacks these commands.

2.0.23 - April 5, 2026

Changed how key-up events are correlated to key-down events for the purpose of determining whether to suppress key-up. A key-down with SendLevel between 1 and 7 now only correlates with a key-up of the same level. When #InputLevel 1 is in effect, this fixes Right::Send "{Right}" not suppressing key-up, RShift::RAlt interfering with RAlt::RShift and vice versa. Events with SendLevel 8 and above are still grouped with non-sent events for practical reasons.

2.0.8 - September 11, 2023

Fixed some issues affecting suppressed Alt/Ctrl/Shift/Win hotkeys, such as:

  • *LCtrl:: blocked LCtrl from the active window, but sending Alt-key combinations would fail because the system thinks Ctrl is down, and would therefore send WM_KEYDOWN instead of WM_SYSKEYDOWN.
  • *LAlt:: caused the system to forget any prior {LAlt DownR}, so a remapping such as LCtrl::LAlt would not behave correctly while LAlt is physically down, even though LAlt was suppressed.
  • Other potential issues where the system's low-level tracking of a modifier key doesn't match up with the logical state.

Fixed some issues affecting continuation sections:

  • Escape sequences in the Join option were translated twice, causing ```` to become one literal ` instead of two, ``n to become a linefeed, and similar.
  • `" or `' produced a literal backtick and ended the string, instead of producing a literal quote mark, if the continuation section was enclosed in quotes of the same type and lacked the ` option.

Optimized the automatic escaping of quote marks and backtick in continuation sections.

Fixed an issue with hotkeys not firing due to a race condition. If a modifier hotkey such as ~*RWin:: called Send or GetKeyState too soon, the OS could report that RWin isn't down, so the hook's modifier state would be "corrected" and hotkeys would wrongly fire or fail to fire. This was likely to occur only if another keyboard hook was installed more recently than the script's own hook, since in that case the OS would not update key state until the other hook's thread has resumed and returned.
